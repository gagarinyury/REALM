# Диагностические инструменты

Три скрипта, выросшие из расследований 10-13.08.2026. Общее у них одно: **все три
отвечают на вопрос о прогоне, не запуская симулятор** (кроме `check_spot.py`, которому
нужен только JSON сцены с диска). Запуск REALM стоит две-пять минут и 6 ГБ видеопамяти,
поэтому проверять гипотезы дешевле так.

## `extract_video.py`

Достаёт mp4 и отдельные кадры из `logs/<эксперимент>/<модель>/videos/<задача>.parquet`.
REALM пишет видео внутрь parquet, и посмотреть его иначе нельзя.

```
python extract_video.py <путь.parquet> <каталог-вывода>
```

Кадры нужны чаще, чем кажется: два дефекта из найденных за эти дни
(деформированные предметы и невыгруженные текстуры) видны только глазом на кадре,
в логах и метриках их нет.

## `reach_check.py`

Отвечает, дотягивался ли робот до предмета — по записанным `qpos`, прямой кинематикой
Panda, без симулятора.

```
python reach_check.py <qpos.parquet> <robot_x> <robot_y> <rot_deg> <obj_x> <obj_y> <obj_z> <метка>
```

Печатает минимальное расстояние схвата до предмета, шаг, на котором оно достигнуто, и
разброс схвата по осям. Порог REACH в `env_base.py` — 0.1 м.

Именно этим выяснилось, что в `Merom_1_int` робот наводится по горизонтали верно, но
никогда не опускает схват ниже 25 см над столешницей — то есть дело не в прицеливании.

## `check_spot.py`

Проверяет точку установки робота по геометрии сцены, читая JSON датасета.

```
python check_spot.py <SCENE> <robot_x> <robot_y> <obj_x> <obj_y> <obj_z>
```

Печатает, что стоит вплотную к роботу, есть ли под точкой спавна предмета
горизонтальная опора и на какой она высоте против заявленной.

Нужен потому, что координаты в `realm/config/scenes/scenes.yaml` пришпилены к версии
датасета: в `Benevolence_1_int` робот оказался в прихожей, в 8.8 м от кухонной стойки,
а в `Merom_1_int` расхождение всего 4 см — но и его хватает, чтобы предметы спавнились
внутри столешницы.
